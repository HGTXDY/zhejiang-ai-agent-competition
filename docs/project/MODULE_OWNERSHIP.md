# 模块分工与协作边界

## 1. 分工原则

- 采用“模块主责 + 对方 Review”，不是各自孤立开发。
- 主责人负责方案、实现、测试、文档和交付；另一位成员负责接口确认和 Code Review。
- 跨模块接口先写契约和测试样例，再并行编码。
- 同一 PR 尽量只修改一个主模块，避免两人同时改动同一批核心文件。

## 5. Review 规则

- 领域 Schema、API 和目标函数变更必须由另一位成员批准；
- 数据标注至少抽查 20%，关键演示菜谱需 100% 复核；
- 调度 PR 必须附冲突、依赖、无解和性能测试；
- 前端 PR 必须附截图或录屏及 mock/真实接口说明；
- Prompt PR 必须附固定测试集前后对比，禁止只凭单个示例判断效果。
