# 决策权与变更流程

## 决策责任矩阵

| 事项 | 提议 | 最终决定 | 执行 |
|---|---|---|---|
| 产品范围、P0/P1/P2 | HGTXDY | HGTXDY | 按 Issue 分配 |
| 技术栈和架构 | HGTXDY | HGTXDY | 对应模块负责人 |
| Schema 和 API | HGTXDY | HGTXDY | 后端定义、前端接入 |
| 调度目标和约束 | HGTXDY | HGTXDY | HGTXDY |
| 页面实现细节 | cbiiro97977 可提议 | HGTXDY 确认关键交互 | cbiiro97977 |
| 菜谱标注细节 | cbiiro97977 可提议 | HGTXDY 按规则抽查确认 | cbiiro97977 |
| 版本发布与验收 | HGTXDY | HGTXDY | 双方配合 |

## 需求变更

1. 在 GitHub 创建或更新 Issue；
2. 说明变更原因、影响模块、兼容性和验收变化；
3. HGTXDY 作出接受、推迟或拒绝决定；
4. 接受后更新 PRD、契约或 ADR；
5. 再分配具体实施任务。

协作成员发现问题时应上报，不要求其自行承担产品或架构决策。
