# 开发路线与里程碑

## M0：规格冻结

完成标准：

- PRD V1.0 入库；
- 技术架构、模块边界和第一版 API 契约由项目负责人冻结；
- 第一阶段测试菜谱和设备配置确定；
- 后端与前端工程脚手架方案确定。

## M1：确定性调度 MVP

范围：固定 JSON、领域模型、规则校验、初始调度、基础甘特图。

完成标准：

- 输入 3～5 道菜和设备配置；
- 输出完整排程 JSON；
- 设备冲突、依赖冲突、单人人工冲突均为 0；
- 前端基础甘特图与排程 JSON 一致；
- 包含正常、资源不足、依赖错误和无解测试。

## M2：自然语言解析

范围：Parser Adapter、Prompt、Schema 校验、归一化和解析评测。

完成标准：

- 官方格式菜谱可转换为调度输入；
- 设备、时间、依赖和人工介入有独立指标；
- 低置信或缺失字段有明确状态；
- 解析失败不会进入调度器。

## M3：多目标优化

范围：同出锅、总时间、连续人工操作、求解差距和性能。

完成标准：

- 输出全部官方相关指标；
- 与串行基线和求解器 bound 对比；
- 硬约束不因权重调整被违反；
- 批量测试达到官方合格线并争取优秀线。

## M4：动态执行与重排

范围：状态机、延迟、临时加菜、设备异常、最小扰动和通知。

完成标准：

- 已完成任务保持不变；
- 重排后无新增冲突；
- 输出结构化差异和扰动指标；
- 通知与最新排程一致；
- 无解和超时有明确降级响应。

## M5：比赛交付

范围：完整 API、Docker、自动评测、测试报告、技术文档和演示。

完成标准：

- 全新环境一条命令启动；
- API 文档与实现一致；
- 演示脚本覆盖初始调度和动态重排；
- 输出性能与正确性报告；
- 所有 P0 Issue 关闭，无高优先级已知缺陷。
