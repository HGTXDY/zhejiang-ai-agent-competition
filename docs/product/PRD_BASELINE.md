## 基线规则

1. 功能范围、优先级和验收标准以本版本 PRD 为准。
2. P0 范围、核心数据模型、硬约束或 API 的破坏性变更，必须通过 Issue 和 PR 审议。
3. 产品需求变更需要更新 PRD 版本；技术取舍通过 `docs/decisions/` 中的 ADR 记录。
4. 开发时先完成固定 JSON 到确定性排程的闭环，再接入大模型解析。
5. PRD 只定义“做什么”；具体实现以技术设计文档为准，但不得降低 PRD 验收标准。

## 已冻结的实现口径

- 解析层只识别 `device_type` 和能力要求，不分配具体 `device_unit`；具体设备实例由调度器分配。
- 菜品完成时间是最后一个必需步骤达到可上桌状态的时间。
- 同出锅时间差为最晚菜品完成时间减去最早菜品完成时间。
- 连续人工操作采用可配置的间隔合并阈值，初始默认 30 秒。
- 目标开饭时间作为软目标；不可按时完成时仍返回最优可行方案和预计延迟。
- 性能同时记录解析、校验、求解、通知和端到端耗时。
