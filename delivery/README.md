# CookFlow 比赛交付包（M0）

本目录用于沉淀比赛现场的启动、验收和演示流程。当前仓库仍处于多 PR 并行开发阶段，后端 FastAPI 与前端控制台尚未全部合并到 `main`，因此本交付包先提供**可重复的交付检查和演示运行规范**，不伪造一个尚未存在的完整 Docker 闭环。

## 交付前检查

在仓库根目录执行：

```bash
./scripts/check-delivery.sh
```

脚本会依次检查：

- Python 与 Node.js 基础环境；
- V1 合同与官方资料校验；
- 已存在的后端测试；
- 已存在的前端 TypeScript / Vite 构建；
- 交付文档和关键目录。

脚本对尚未合并的模块会明确标记 `SKIP`，不会把缺失模块误报为通过。

## 演示运行

```bash
./scripts/run-demo.sh
```

当前脚本会检测前端和后端是否已经合并：

- 前端存在时启动 Vite 开发服务器；
- 后端存在时输出后端启动要求；
- 任一模块未就绪时给出阻塞原因和下一步动作。

后端 API、Docker Compose 和性能压测必须在 FastAPI 主入口确定后补齐，不能在入口不存在时提交不可运行的容器配置。

## 比赛现场演示顺序

1. 启动服务并确认健康检查；
2. 打开 CookFlow 排程总览；
3. 展示四道菜正常排程；
4. 上报任务延迟，查看状态变化和通知；
5. 上报设备不可用，查看重排差异；
6. 临时加菜，查看新增任务和重排信息；
7. 展示约束状态、任务锁定状态和事件日志；
8. 保存最终排程快照。

## 当前明确限制

- 本目录不是官方 Gold Label 数据集；
- `fixtures/v1` 仅用于契约、冒烟和联调；
- 在后端入口合并前，不声明已完成真实 API 闭环；
- Docker 镜像与性能基线将在后端入口、前端原型和配置项稳定后补充。
