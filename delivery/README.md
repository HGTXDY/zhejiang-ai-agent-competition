# CookFlow 比赛交付包（M0）

本目录用于沉淀比赛现场的启动、验收和演示流程。当前仓库已包含 FastAPI 后端、React 前端、契约校验、调度器和执行状态模块。本交付包提供可重复的交付检查和演示运行规范；Docker/Compose 仍列为 M5 交付项，尚未宣称已完成。

## 交付前检查

在仓库根目录执行：

```bash
./scripts/check-delivery.sh
```

脚本会依次检查：

- Python 与 Node.js 基础环境；
- V1 合同与官方资料校验；
- 已存在的后端测试；
- 已存在的前端 TypeScript / Vite 构建；
- 交付文档和关键目录。

脚本将后端回归测试和前端生产构建作为硬门禁；缺少产品模块会直接失败，不会把缺失模块误报为通过。

## 演示运行

```bash
./scripts/run-demo.sh
```

当前脚本会检查前端和后端是否存在并启动可演示版本：

- 前端存在时启动 Vite 开发服务器；
- 后端入口存在时给出独立启动命令；
- 任一模块未就绪时给出阻塞原因和下一步动作。

后端 API 已提供初始排程接口；动态重排端点、Docker Compose 和完整性能报告仍按路线补齐，不能把尚未实现的能力写成已交付。

## 比赛现场演示顺序

1. 启动服务并确认健康检查；
2. 打开 CookFlow 排程总览；
3. 展示四道菜正常排程；
4. 上报任务延迟，查看状态变化和通知；
5. 上报设备不可用，查看重排差异；
6. 临时加菜，查看新增任务和重排信息；
7. 展示约束状态、任务锁定状态和事件日志；
8. 保存最终排程快照。

## 当前明确限制

- 本目录不是官方 Gold Label 数据集；
- `fixtures/v1` 仅用于契约、冒烟和联调；
- 前端支持 Mock 与 HTTP 两种适配模式；演示必须明确当前模式，动态事件/重排在对应 API 合并前仍使用 Mock。
- 动态事件/重排 API 合并前，不声明已完成真实 API 闭环。
- 完整性能基线仍是 M5 的未完成项。

## Docker/Compose 全栈运行

需要 Docker Desktop 或兼容 Docker Compose v2 的环境：

```bash
docker compose up --build
```

- API：`http://127.0.0.1:8000/health`
- 前端：`http://127.0.0.1:8080`
- 自动冒烟：`./scripts/compose-smoke.sh`

当前 Compose 验证初始排程 API 和前端 HTTP 适配；动态事件/重排 API 合并后再扩展对应验收场景。
